# BrownDust2 戦闘・実機検証マトリクス

最終確認日: 2026-09-03（Asia/Tokyo）

## 1. 完了条件

この文書の目的は「分からない箇所を列挙すること」ではなく、現行クライアントから再現に必要な事実を取り出すための受け入れ試験を定義することである。各ケースは次の一式がそろったときだけ `VERIFIED` とする。

- クライアントビルド番号、コンテンツ、難易度、日時
- 味方・敵・コスチューム・装備・成長値の完全な入力
- 初期盤面、行動順、使用スキル、バースト段階
- 各ヒット前後のHP、SP、チェイン、効果、CT、座標
- 乱数の影響を排除したケース、または十分な反復と全結果
- 画面録画または連続スクリーンショット
- シミュレータのイベントログとの差分がゼロであること

`OBSERVED` は実機1ケースで一致、`VERIFIED` は実機で境界値を含む独立2ケース以上が一致、`REGRESSION` はその実機結果を自動回帰テストへ登録済みであることを表す。`SOURCE_REGRESSION` は公開データまたは攻略資料から作った期待値に対する自動テストであり、実機一致をまだ証明しない。`IMPLEMENTATION_REGRESSION` は決定性、API、テンソル形状などリポジトリ内部の契約を自動検査しているが、ゲームクライアントの正解値とは比較していないことを示す。`CLIENT_TODO` は実機採取待ちである。

## 9. ゴールデントレース形式

各検証結果は、次の論理項目を満たす機械可読データとして保存する。動画だけを正解データにしない。

```yaml
trace_id: MODE-01-mirror-sp-001
client_build: 2.33.15
observed_at: 2026-08-28T12:00:00+09:00
mode: mirror_war
seed_visibility: unknown
initial_state: {}
submitted_actions: []
expected_events:
  - seq: 1
    type: TURN_STARTED
    side: attacker
    sp_before: 5
    sp_after: 5
  - seq: 2
    type: ACTION_STARTED
    actor_id: example
  - seq: 99
    type: TURN_ENDED
    side: attacker
  - seq: 100
    type: SP_CHANGED
    side: attacker
    delta: 6
  - seq: 101
    type: SP_CHANGED
    side: defender
    delta: 6
assertions: []
evidence:
  video: null
  screenshots: []
status: OBSERVED
```

クライアントビルド番号は例示であり、採取時の実値を必ず記録する。最新仕様へ更新した後は、旧ビルドのトレースを現行受け入れ試験へ混在させない。
