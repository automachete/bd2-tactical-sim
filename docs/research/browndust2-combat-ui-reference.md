## 根拠の優先順位

1. 現行の公式告知・ゲーム内ヘルプ・公式データを仕様の第一根拠とする。
2. 更新時点の新しい韓国語プレイ動画を、画面遷移と操作フィードバックの照合に使う。
3. 公式GitBookは基本操作の根拠にするが、更新が古いページのSP値やモード制約は採用しない。
4. ローカルデモは入力実装の発見にだけ用い、見た目・数値・挙動を無検証で移植しない。
5. シミュレータ独自のデバッグ操作は「デバッグ拡張」と明示し、ゲーム由来の操作と混同しない。

## 画面構造の照合基準

1. 戦闘は独立したカードや管理画面の中ではなく、16:9の戦場全面を占める。
2. 味方は左端、敵は右端の縦型レールへ並ぶ。各項目には顔、HP、行動順または状態を重ねる。
3. 中央は操作判定が曖昧にならない見下ろし専用の3×4マスとする。遠近ビューやビュー切替は設けない。
4. 味方を選んだときだけ、キャラクター名、属性、選択中スキル、SP、クールダウン、効果要約、範囲、コスチューム列を表示する。
5. スキル選択は即時実行ではなく「予約」である。全ユニットの予約と順番を確認してから下部右の開始ボタンで一括実行する。
6. 順番変更は左レールのカード自体をドラッグして行い、番号の即時更新でフィードバックする。ゲームに存在しない専用の「順番編集モード」や常設上下ボタンは設けない。
7. SPは数値だけでなく、下中央の残量ピップでも表示する。ピップの形・色は公式素材を模写せず、独自のモダンUI表現にする。
8. 編成、プリセット、詳細ログ、MCTS設定は常設のサイドバーにせず、戦場の上へ開く画面またはドロワーにまとめる。
9. モンスターチェイサーでは右側を通常の敵レールではなく、ボスHPとルール定義済み行動予告へ切り替える。PLAYERはTEAM 1/2を保持する。
10. 端末幅が狭い場合も戦場の比率を壊さず、縮小または横スクロールで同じ位置関係を維持する。

## 実装上の操作状態

| UI状態 | 入力 | 結果 |
|---|---|---|
| 未選択 | 味方の顔または盤面ユニットを選択 | そのユニットの利用可能コマンド列を開く |
| 選択中 | コスチューム／通常攻撃／ノックバックを選択 | 選択を予約し、SP予定値と行動番号を更新する。プレイヤー任意の待機行動は存在しない |
| 予約済み | 左レールのカードをドラッグ | 予約内容を保ったまま全員の行動順を入れ替える |
| 計画確定 | 戦闘開始 | 予約コマンドを現在の並び順でシミュレータへ一括送信する |
| 敵選択 | 敵の顔または盤面ユニットを選択 | HP、位置、状態効果を検査用ポップアップに表示する |
| 編成画面 | マス／キャラクター／コスチュームを変更 | 戦闘開始時に外部カタログからセットアップを再構築する |
| 戦闘準備 | 味方駒を空きマスへドラッグ | 駒を移動し、送信予定の配置とマス表示を即時更新する |
| 戦闘準備 | 味方駒を味方のいるマスへドラッグ | 2体の位置を入れ替える |
| 戦闘準備 | キーボードで駒を持ち上げ、移動、確定 | D&Dと同じ移動／入替結果になる。Escで取り消す |
| 配置固定モード | 駒をドラッグ | 無効理由を表示し、配置も送信データも変えない |
| モンスターチェイサー | 戦闘開始 | PLAYER予約を実行後、敵のルールベース手番を自動実行する |

## シミュレータ固有の視覚設計

ゲーム準拠の対象は戦闘操作、情報階層、状態遷移、入力結果であり、色・装飾・公式素材ではない。シミュレータはFluent 2を参考に、暗色の中立面、単一の青いアクセント、角丸、システムUI書体、フラットな塗りを使う。盤面、ボタン、HP、ボス表示を含め、装飾目的の金色、木・革・紙を連想させる色、背景グラデーション、セリフ体を使わない。味方・敵の色はラベルと状態表示に限定し、通常セルは中立色とする。

3×4セルはCSSの`aspect-ratio: 1`を不変条件とし、ビューポート幅・高さに応じて盤面全体を縮尺する。戦闘準備、停止、ログ、詳細設定は同一のモーダル階層を使い、子ダイアログが親の背面へ隠れないことを実ブラウザで検査する。表示文言は`ja-JP`言語資源から取得し、HP、SP、CT、MCTS、JSON等の技術略語を除いて日本語へ統一する。キャラクター名・コスチューム名・スキル名は機械翻訳せず、公式日本語表記を外部ローカライズデータとして管理する。

## デバッグ拡張

- MCTSへプレイヤー手番を任せる。
- 同じセットアップとシードでリセットする。
- 直前のプレイヤー手番開始時点へ巻き戻す。
- 乱数シード、MCTS探索回数、装備補正JSONを編集する。

これらは検証を容易にするシミュレータ機能であり、BrownDust2本体の操作として扱わない。

## 画像表現の境界

本シミュレータは戦闘ロジック検証用であり、公式クライアントや第三者ミラーの画像・3Dモデル・アニメーション・音声・背景素材を取得、埋込、再配布しない。キャラクターは名前、属性、攻撃種別、外部DB由来の数値と、CSSで生成した抽象トークンだけで識別する。戦場、エフェクト、アイコンもHTML/CSSの独自表現とする。照合対象は操作階層、入力結果、予約フィードバック、コンテンツ別HUDであり、公式アートの複製ではない。
