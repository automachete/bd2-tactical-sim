# 予測・予約・実行整合性検証（2026-09-04）

## 結論

チーム手番で受理したスキルは、予約時に確定したSP費用で実行する。先行行動によるSP残量の変化は、後続の予約済みスキルを通常攻撃へ置換する条件にならない。行動者の死亡・行動不能など、受理後に実行不能となった行動は理由付きでスキップする。

ゴールデンコロシアムでは、デスタイム中にスキルを合法手から除外し、通常攻撃を選択する。このモード固有の行動選択は、予約済み行動の実行契約から分離する。

## 準拠規則

- チーム手番の受理時に、行動順に沿って全コマンドと共有SP予算を検証し、各スキルの予約時SP費用を固定する。
- 予約済みの固定費用スキルは、先行行動が現在SPを増減しても再度合法性を失わない。残SP全消費スキルだけは、そのスキル実行時の残SPを消費する。
- 受理後に死亡、行動不能、沈黙等で実行不能になったコマンドは`ACTION_SKIPPED`とし、通常攻撃を暗黙に追加しない。
- ゴールデンコロシアムのデスタイムは、実行失敗後の差替えではなく、スキルを合法手から除外して通常攻撃を自動選択する。
- UIは選択したコマンドを表示し続け、予測器が別コマンドへ差し替えることを正当な表示状態として扱わない。

## 全件検証鎖

外部原表から実行結果までを、次の二段で接続した。

1. `npm --prefix tools run validate:catalog`
   - 66キャラクター、164衣装、12,509派生を対象とする。
   - 外部原表の分類済みフィールド、SP、CT、打撃数、対象、範囲、強化、潜在力、バースト、数値プレースホルダーを450,463項目で照合する。
   - 12,509派生から得られる型付き命令は35,462件、18種である。
2. `cargo run -p bd2-data --bin bd2-quality -- --episodes 4 --rounds 1 --max-steps 128`
   - 同じ12,509派生をネイティブ戦闘コアで全件実行する。

## 規則・境界・統合回帰

- SP予約はキャラクター固有データを使わず、後続費用0～20の全値と、先行SP変化`i32::MIN`、-20、-6、-1、0、1、6、20、`i32::MAX`の直積で検査する。
- 動的に沈黙した予約行動は1件のスキップで終了し、通常攻撃の`ACTION_STARTED`が追加されないことを検査する。
- HTTP予測と実行イベントは、後続予約技が先行SP減少後も同じ衣装IDで解決されることを検査する。
- 実ブラウザは、予約表示、選択スキル名、予測、戦闘開始後の実`ACTION_STARTED`が同じ衣装IDであり、`ACTION_SKIPPED`がないことを検査する。
- ノックバックは8方向の共通オフセット、両陣営の向き、全盤面端、全隣接障害物、衝突をネイティブ規則で検査し、GUI表示ベクトル・予測移動・実移動を同一データへ接続する。
- 範囲はネイティブの`TARGET_AREA_RESOLVED`を予測と実行の共通結果とし、端クリップ、重複除去、障害物、複数対象、死亡・召喚を検査する。

## モード適用範囲

通常戦闘と鏡戦争は同じ予約行動の実行契約を使用する。鏡戦争では、`MODE-02A`に定義した初期SP、手番回復SP、先制処理、死亡者スキップを追加適用する。ゴールデンコロシアムのデスタイム時通常攻撃は専用スケジューラが選択する。同時全滅、時間切れ、レート増減の引き分け規定は`MODE-02C`として別に管理する。
