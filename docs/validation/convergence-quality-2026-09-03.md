# 収束型品質検証記録（2026-09-03）

## 結論

通常戦闘、鏡戦争、魔物追跡者、ゴールデンコロシアムを対象に、状態付きランダム探索、独立不変条件、スナップショット再実行、カタログ全派生実行、モデルベースGUI操作、重点ミューテーションテストを実施した。最終探索では、独立した3ラウンドで各100,000戦、合計300,000戦を実行し、新規の状態不変条件違反は0件だった。GUIは1,000系列、1,680ターンを完走し、観測したコア状態とDOMの不一致は0件だった。

この記録が保証するのは、収録済みルールとデータに対する内部整合性、決定性、実行可能性である。実機動画とのイベント順序差分照合は依頼により後続作業へ延期しており、今回の合格結果には含めていない。このため、未照合の実機挙動まで完全一致したという意味ではない。

機械可読な結果は次の3ファイルに保存した。

- `convergence-quality-2026-09-03.json`: 戦闘コア、カタログ、復元、独立不変条件
- `convergence-gui-2026-09-03.json`: GUIモデル操作

3つの探索ラウンドは異なる64 bit seedから開始し、それぞれ100,000戦を実行した。各ラウンドとも4モードを25,000戦ずつ含み、新規不具合0件で終了した。状態付きシミュレーションは行動種別、順番、配置、衣装派生を変化させ、各遷移後にSP、盤面、行動順、効果、イベント列、ダメージ台帳、モード固有状態、終了状態を検査した。

Rust側ではproptestによる任意seed・任意モード・複数ターンの復元再実行、破損スナップショットの原子的拒否、通常攻撃の独立整数オラクルを各256ケース実行した。Python側ではHypothesisのルールベース状態機械により、4モードで前進、復元、破損入力、再実行を組み合わせた。

GUI系列は通常戦闘、鏡戦争、魔物追跡者、ゴールデンコロシアムを循環し、衣装選択、バースト段階変更、行動順ドラッグ、配置ドラッグ、速度変更、複数ターン実行を実ブラウザから操作した。各操作後に、生存ユニットの全配置、SP、ターン、モード、正方形セル、待機コマンド不在、通信エラー、ブラウザ例外をコア状態と照合した。

## 検出して修正した共通原因

1. 復元時のイベント履歴検証が、イベント番号の欠落やライフサイクル矛盾を受理していた。イベント列を単一走査で検査し、開始・終了イベント、連番、SP境界、ダメージ・回復数値、終了後の行動をfail-closedで拒否するようにした。状態に残っていた未使用の`pending_events`も削除した。
2. 魔物追跡者の条件付きボススキルが通常の予約行動経路を迂回し、沈黙または行動不能中でも発火を試みていた。衣装行動の禁止判定を共通化し、条件発火側でも死亡、行動不能、沈黙を同じ契約で扱うようにした。初回300,000戦探索で得た12件の失敗系列を最小化し、発火成立、使用上限、カウンタ更新、死亡、行動不能、沈黙を独立した回帰テストにした。
3. データ同期処理に、未知の能力参照を攻撃力へ寄せる処理、期間不明を1ターンにする処理、魔物スキル順が不明な場合に末尾へ送る処理が残っていた。すべて例外終了へ変更し、1回消費型効果だけは根拠を明示した期間指定として保持した。現行データを再同期し、既存カタログとの意味的同一性を確認した。
4. GUIのセッション切替時に、旧画面の対象プレビューが新しい戦闘へ到達する競合があった。旧documentを破棄してから新セッションを開始し、モード・ターン・行動番号を待つ同期条件を追加した。また、画面遷移でクライアントが静的ファイル受信を中止した際の接続切断を、開発サーバーが例外として記録し続ける問題を全レスポンス共通で処理した。
5. Pythonバッチ環境が各フレームをJSON化してからNumPyへ戻しており、学習入力のボトルネックになっていた。Rustから型付きNumPy配列を直接返す経路へ統合し、旧JSON経路との値・shape・dtypeの完全一致を回帰テストにした。
6. SP上限のGUI回帰テストが、耐久性のない鏡戦争プリセットに依存し、上限到達前の全滅を「20→20イベント欠落」と誤診していた。両陣営を十分なシールドで保護した専用シナリオに変更し、上限到達後の回復イベントとHUDを実際に観測するよう修正した。

## ミューテーション収束

復元イベント履歴の検証へ59件の変異を注入し、58件をテストで検出した。残る1件はmatch arm削除によるコンパイル不能で、実行可能な生存変異は0件だった。

条件付きボススキルと共通衣装禁止判定へ28件の変異を注入した。第1ラウンドでは10件が生存し、条件成立、使用上限、発火回数、死亡・行動不能境界を追加した。第2ラウンドの生存1件は、デスタイム前のゴールデンコロシアムで衣装スキルが使用可能であるという反対側境界の欠落だった。これを追加した第3ラウンドでは28件すべてを検出した。

## 性能

同一の64並列・12,800環境stepで、旧JSON経路は5,827.6 step/s、NumPy直接経路は51,805.7 step/sだった。CPUバッチ入力は8.89倍に改善した。NVIDIA GeForce RTX 5070 Tiへの入力転送は541,191.9 frame/s、検証用ネットワークのforwardは36,417.4 frame/sだった。測定時のPythonは3.13.7、PyTorchは2.13.0+cu130である。
