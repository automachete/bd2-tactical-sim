# UI・ゲームプレイ複合バグ監査（2026-09-01）

対象はデバッグプレイヤーの行動予約、対象プレビュー、実行演出、通常戦闘、鏡戦争、モンスターチェイサーである。要素の存在だけを調べるテストではなく、配置変更、順番変更、複数予約、対象解決、手番実行、次ターン、召喚、魔物遷移を連結したシナリオで検証した。

## 発見・修正した不具合

1. 対象確認APIだけが確定済みの凸・潜在力バリアント範囲を受け取らず、範囲技を単体として返していた。通常の合法手と同じ `command_metadata` を付与して解消した。
2. 後続ユニットの対象確認で、先行して予約した攻撃をすべて待機へ置換していた。予約済み全行動を順番どおり一時実行するよう修正した。
3. 先行行動による撃破、復活、ノックバック後も、後続ユニットの範囲内ユニットを手番開始時の生存状態・座標から計算していた。一時実行イベントを対象確定位置まで反映するよう修正した。
4. 行動順カードを別カードへ落とす操作が常に「直前へ挿入」になり、最後尾へ移動できなかった。カード上半分／下半分とレール末尾を別の挿入位置として扱うよう修正した。
5. 行動順変更がHTML Drag and Dropだけで、タッチ操作に反応しなかった。Pointer Eventsによる同一の前後挿入操作を追加した。
6. 使用後にクールタイムへ入ったコスチュームが候補一覧から消えていた。装備中だが現在使えないコスチュームをサーバー応答へ残し、残りCTと使用不可理由を表示するよう修正した。
7. 自動予約がプレイヤーの手動選択を捨て、SP消費量が最大の技へ勝手に置換していた。手動選択を最優先し、未選択時は装備順で予約するよう修正した。
8. 戦闘準備の詳細セレクターでは、同じチームに編成済みのキャラクターへ変更できた。キャラクターピッカーと同じ重複禁止を詳細セレクターにも適用した。
9. コスチュームリンク先のコスチュームを無効化してもリンクが残り、戦闘開始時に不正ロードアウトとなった。無効化と同時にリンクを解除し、無効コスチュームをリンク候補から選べなくした。
10. 固定セル攻撃の `TARGET_CELL_LOCKED` を演出が無視し、誰がどのマスを狙ったか表示されなかった。対象セルの白枠、効果範囲色、攻撃者からの線、座標表示を追加した。
11. `UNIT_SUMMONED` を演出が無視し、召喚後のイベントが存在しない駒を対象にしていた。イベント時点で新しい駒を盤面へ挿入し、以降のダメージ・移動演出が同じ駒へ作用するよう修正した。
12. モンスターチェイサーの `MONSTER_PARTY_ACTIVATED` を無視し、チーム交替が全イベント再生後まで見えなかった。交替イベント時点で次チームを盤面へ展開するよう修正した。
13. `MONSTER_LEVEL_ADVANCED` を無視し、魔物レベル遷移と超過ダメージが見えなかった。レベル遷移キューとHUD更新を追加した。
14. `SP_CHANGED` を演出が無視し、戦闘中のSPゲージが予約時の値のままだった。プレイヤー側SPイベントごとに数値とピップを更新するよう修正した。
15. モンスターチェイサーHUDが廃止済みフィールド `shared_hp` / `selected_level_hp` を参照し、HP比率が `NaN` になっていた。現行の `battle_hp_remaining` と `level_hp_segments` のみに統一した。
16. `BARRIER_ABSORBED` を演出が無視していた。吸収量のフローティング表示と戦闘キューを追加した。
17. ページ再読込時に、戦闘中の編成・配置・装備・シード・MCTS設定ではなく既定プリセットを編集画面へ戻していた。サーバーが現在の完全なセットアップを返し、クライアントがそれを復元するよう修正した。
18. 召喚体と魔物本体を公開エンティティ一覧から除外していたため、戦闘中の駒名が内部IDになっていた。プレイ可能キャラクター一覧とは分離したシステムエンティティ一覧を追加し、公式固有名を解決するよう修正した。
19. 召喚体の固有スキルを公開コスチューム一覧から除外していたため、召喚後の手番に攻撃範囲・SP・CTを表示できなかった。システムコスチュームとして公開し、通常の合法手と同じメタデータ経路へ統合した。
20. 魔物本体の駒名が内部ID `fiend:10072` のまま表示されていた。システムエンティティの公式名解決を敵一覧・行動順・盤面・演出へ一貫して適用した。
21. 魔物スキルの複合条件を文字列化せず、対象確認へ `[object Object]` と表示していた。条件ASTを日本語の説明へ変換する専用処理を追加した。
22. 条件分岐・即死・タグ解除など一部の効果説明へDB上の英語命令名を露出していた。型ごとの日本語説明を追加し、機械的な内部表現をUIから排除した。
23. 装備コスチュームをすべて無効化でき、開始時に不正な空ロードアウトを作れた。最後の一着は無効化できない制約をUIとテストへ追加した。
24. 戦闘準備ダイアログをEscまたは標準の閉じる操作で閉じると、詳細編集ポップオーバーだけが残った。全クローズ経路で一時UI状態を破棄するよう統一した。
25. 戦闘準備中にも自動手番タイマーが進み、背面で敵・プレイヤーが行動していた。開いているモーダルがある間は予約も実行も停止するよう修正した。
26. 戦闘不能ユニットを盤面の占有者として描画・送信し続け、生存ユニットの移動先を隠していた。生存中の駒だけを配置操作と形成更新の対象にした。
27. ノックバック衝突で `COLLISION_DAMAGE` と `DAMAGE_APPLIED` の双方が同じダメージ数値を表示していた。前者を衝突説明、後者を唯一の確定ダメージ表示として役割分担した。
28. `CHAIN_CHANGED` を再生処理が無視し、チェインの増加が視覚的に分からなかった。対象上のチェイン表示とイベント説明を追加した。
29. 装備DBにあるSP増減・CT増減・被ダメージ軽減などの非基礎能力補正を、エンジン初期化時に捨てていた。永続パッシブ補正としてユニット状態へ保持し、全能力計算へ合成した。
30. 装備・効果によるSP消費量とCTの補正を合法手には反映しても、行動カードの表示値には反映していなかった。表示メタデータも実行時と同じ実効補正から算出するよう修正した。
31. 強化学習環境を敵側操作にすると、リセット直後がプレイヤー手番のまま観測された。操作側の手番まで相手を進めてから観測を返すよう修正した。
32. 敵側操作の強化学習環境でも勝敗報酬をプレイヤー視点で返していた。操作側を基準に終局報酬の符号を決めるよう修正した。
33. 強化学習環境の操作側指定が大小文字に依存し、不正値も遅れて失敗していた。初期化時に正規化し、`PLAYER` / `ENEMY` 以外を即時拒否するよう修正した。
34. プレイヤー行動成功後の敵AI行動が失敗すると、APIはエラーなのにプレイヤー行動だけ確定していた。プレイヤー・敵の連続処理を一つのトランザクションとして復元可能にした。
35. 戦闘エンジンが不正なターンを途中まで適用してからエラーを返し、戦闘不能ユニットの再配置も許していた。ターン開始状態へ完全復元し、非活動ユニットの配置を拒否するよう修正した。
36. シード・MCTS回数・深さ・分岐数などへ小数や過大値を渡すと、暗黙切り捨てまたは無制限実行になった。整数性と安全な上限をサーバー側で検証し、拒否時に戦闘状態を保持するよう修正した。
37. 先行行動で新たに召喚された駒を後続範囲技の対象予測へ含めていなかった。予測イベント中の召喚を一時状態へ追加し、同一ターン後続技の対象・占有・範囲判定へ反映した。
38. 戦闘履歴が内部イベント種別、フィールド名、効果IDを生JSONのまま表示し、終局演出も `WIN` などの列挙値を露出していた。全イベントを日本語の意味表現へ変換し、状態効果も型付き内容から要約するよう修正した。
39. 手番・対象確認APIが行動番号、順番、配置座標の小数を暗黙に整数へ丸め、JSON本文のルートやユニット要素が配列・文字列の場合は応答スレッドを例外終了させていた。入れ子を含む全入力を厳密検証し、400応答と戦闘状態の原子性を保証した。
40. 選択・予約・順番変更の各再描画が対象確認を即時送信し、毎回DBから一時シミュレーターを再生成していた。連続操作で要求が滞留し、最新範囲が表示されず別APIも接続できなくなった。専用シミュレーターの再利用、120msの集約、旧要求の中断により、8回の連続予測を約0.01秒で処理できるようにした。
41. モンスターチェイサーの総HPゲージが手番演出中に更新されず、全イベント終了後だけ最終値へ飛んでいた。魔物部位への各ダメージ・回復イベントの確定HPを使って、演出と同時にゲージ・割合・数値を更新するよう修正した。
42. モンスターチェイサーへ切り替えた場合だけMCTS入力のブラウザ検証を省略し、無効値がサーバーで初めて拒否されていた。全モードでセッション設定として同じ入力検証を行うよう統一した。
43. 終局画面が全操作面を覆う一方で戦闘履歴への導線がなく、勝敗確定後にイベント列を調査できなかった。終局画面から最前面の戦闘記録を開き、閉じると同じ勝敗画面へ戻れるようにした。

## 回帰検証

- Python統合テストは、確定範囲、盤端クリップ、実対象、予定配置、先行撃破後の再ターゲット、順番依存の味方対象、実際のイベントログとの一致、クールタイム候補の残存を検証する。
- JavaScriptモデルテストは、3×4盤面の全12アンカーと複数の非対称範囲を独立実装の参照値と照合し、長い予約変更列でSPが負にならず拒否操作が状態を壊さないことを検証する。
- ブラウザE2Eは、左二列の予約導線、マウス／タッチ／キーボード操作、末尾挿入、配置・順番・複数予約を含む実手番、先行撃破後の対象変更、味方順番対象、使用後CT、召喚、固定セル攻撃、SP変化、魔物HP、魔物レベル遷移、チーム交替を実ブラウザで検証する。
- さらに全★5キャラクターをDBから列挙し、現在合法な通常攻撃・全コスチューム技について、GUI予測の主対象・基準マス・効果範囲・実対象を独立した実戦エンジンのイベントログと全件照合する。
- ブラウザE2Eは、現在セットアップの再読込、召喚後の次手番、装備による実効SP、チェイン、衝突、モーダル中の自動進行停止、不正入力の原子性も、複数ターンを進めて検証する。
